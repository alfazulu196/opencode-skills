# Локальный ИИ (ollama) в офлайн-приложении

Принцип поля: всё локально, без облака/логина/синхронизации. Ollama на
`http://127.0.0.1:11434` (или соседней машине по LAN).

## Доступность — быстро и по-человечески

`ollama_status()` → `(ok, reason)` с **коротким таймаутом** (мёртвый порт
не должен висеть): проверка `/api/tags` за доли секунды. Не ok →
кнопка фичи `setEnabled(False)` с тултипом-причиной и
`QMessageBox.information` при открытии диалога: «Распознавание
недоступно: <reason>. Остальные функции работают».

## Structured output с деградацией

Запрос поля `format` тремя уровнями, с логом выбранного уровня:

1. `format` = JSON-схема (надёжно, если модель поддерживает);
2. при ошибке формата → повтор с `format = "json"`;
3. далее без `format` + парсинг из текста (JSON в code-fences,
   произвольный prose — резать регексами).

**Непарсируемый ответ → один повтор** того же уровня, затем деградация.
Каждая попытка в журнал: `format_used` — по нему дебрифинг качества.
Ответ валидировать pydantic-моделью или strict-функцией: алиасы
русских/английских полей, дефолты, cap на число устройств.

## Стрим + отмена

`stream: true`, читать NDJSON построчно → сигнал `progress(str)` в UI
(живой статус «что модель печатает»). Отмена: `cancel_check` —
замыкание/флаг, проверяемый между чанками; обрыв «на ближайшем чанке».
UI: кнопка «⏹ Стоп» (видна только во время генерации), отмена при
закрытии диалога, `cancel_check` учитывается в журнале (счётчик
отменённых кадров — сигнал плохого промпта).

## Warmup и vision-модели

- Модель грузить в память заранее (WarmupWorker при открытии диалога):
  холодный старт 30-60 с убивает UX.
- Vision-модели: qwen2.5vl-класс. При HTTP 400 — уменьшить кадр
  (шринк изображения, повтор с меньшим payload). Кандидаты моделей
  по приоритету; при отказе — фолбэк на следующую.
- Таймауты: генерация на CPU до 2-3 минут — честный текст «это не
  зависло» в статус.

## Воркеры и поток

Генерация — в QThread-воркере, UI не блокируется; паттерн
`detach_running(worker)`: перед новым запуском отвязать/отменить
старый, при закрытии — cancel всех. Сигналы: `progress`, `analysed`
(результат + путь кадра), ошибки — в статус-лейбл.

## Журнал и дебрифинг качества

Каждую попытку в `data/logs/<feature>_log.jsonl`:
время, модель, `format_used`, длительность, отмены, сырой ответ/ошибка.
Инструмент дебрифинга (`tools/debrief_report.py`) сводит: сколько
кадров, разбивка по format_used, отменённые, среднее время. По журналу:
отбор худших кадров → bench → правка промпта.

## Паритет промпта

Промпт — переменная кода + добавления версии. Зафиксировать тестом:
`test_prompt_matches_prompt_lab_combo` — промпт в коде обязан
побайтно совпадать с эталоном промпт-лабы, иначе молча «улучшают» и
теряется трекинг качества.

## Автоподбор модели

Не хардкодить имя модели: `GET /api/tags` → взять первую установленную
(или по приоритетному списку кандидатов), фолбэк на дефолтную. Список
моделей меняется от машины к машине — код должен работать на любой.

## Языковая дисциплина малых моделей

Qwen-класс уезжает в китайский посреди русского ответа. Двухуровневая
защита: системный промпт «ANSWER ONLY IN RUSSIAN» + `stop`-токены на
ключевые иероглифы (`"未成年"`, `"学生"`, `"中文"`, `"翻译"`, `"请"`, `"的"`...) —
запрет на уровне токенов работает надёжнее слов. Против зацикливания:
`temperature: 0.3, top_p: 0.85, repeat_penalty: 1.3`.

## Аналитический отчёт без чата

Для разовых отчётов — `stream: False` (`/api/generate` или `/api/chat`).
Контекст собирать заранее: сырые логи + готовая база CLI-знаний
(hardening-команды). В промпте: роль, «только по-русски», «без
приветствий», жёсткий лимит длины («максимум 25 строк», «только
действия»). ИИ не блокирует отчёт: если ollama не отвечает — отчёт всё
равно выпускается с заглушкой «Вердикт недоступен (Ollama не отвечала
на момент прогона)».
